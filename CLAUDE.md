# My Agent Project

An AI agent project built and maintained with Claude Code.

**Purpose:** Modello Tests Fixer: an agent that repairs a course's modello model config (`model-parameters/map/edges.json`) when its generated Cypress tests fail. For EverFi course repos (e.g. digital-banking, grow) that use the `modello` CLI. Details in `docs/architecture.md`.

## Commands
Node 20+, TypeScript, Claude Agent SDK.
- Install: `npm install`
- Run (dry-run): `npm run dev -- --project <course-root> [--spec <file>]`; add `--write` to apply changes. Needs an Anthropic credential and spends money (`--max-budget-usd`, default 5).
- Test (all): `npm test`
- Test (single): `npx vitest run test/guard.test.ts` (add `-t "<name>"` for one case)
- Typecheck: `npm run typecheck`
- Build/run of the target course goes through ECC (`ecc --script test:build`; `--local` uses `test:local`) and `modello run` (per spec, JUnit). Needs `ecc`, `yq`, `modello` on PATH; preflight checks this. Override with `--build-cmd` / `--run-cmd`.

## Repo notes
- `setup.sh` is one-time bootstrap (git init, initial commit, optional private GitHub repo via `gh`). Don't rerun it casually.
- `.claude/settings.json` allows read-only git commands and `ls`, and denies reading `.env*` and `rm -rf`.
- Personal overrides go in `CLAUDE.local.md` (gitignored). Keep this file under ~200 lines; put longer material in `docs/` and pull it in with `@docs/file.md`.
- `.claude/skills/` holds `code-review`, `wrap-up`, `ecc-course-dev` (ECC/Furnace setup and course builds) and `modello-tests` (generate/run/fix course Cypress tests) and `course-pr` (branch, commit and PR in a course repo); `.claude/agents/` holds `reviewer` and `researcher`.
- Real course checkouts live in `/Users/jay/everfi/git/courses` (digital-banking, adult-learning-modules, future-smart-2). Claude may run `ecc --script test:build` and the fixer with `--write` there; the owner reviews and keeps or discards course changes manually. Commits, pushes and PRs in a course repo happen only through the `course-pr` skill, on a branch, after the owner confirms the text. `test/ui/cypress/e2e` is gitignored and regenerated by the build.
- Failure page/block can be recovered manually: read the failing selector and step from the Cypress screenshot, then search the generated spec for it; the JUnit stack alone won't tell you.
- Stubbed tests hide real-run bugs (e.g. `modello run` needs an absolute `--spec`); verify run/build changes against a real course copy.

## Rules
- Plan first for any change touching more than 2 files; wait for approval. Exempt: `/init` and `/wrap-up`, which update docs and may touch several files.
- Run tests before saying a task is done (once a test command exists).
- Never commit secrets or `.env` files.
- Small, focused commits with clear messages.
- Don't add dependencies without asking.
